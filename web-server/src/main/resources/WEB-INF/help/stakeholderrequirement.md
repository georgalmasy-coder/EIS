# Stakeholder Requirement

This page is used to view, create, edit, import and export stakeholder requirements for the selected project.

Stakeholder requirements describe needs, expectations, constraints or requests from stakeholders. These requirements can later be linked to system requirements and other engineering information.

## What does this page show?

The page shows a table of stakeholder requirements.

At the top of the page, you can see:

- customer name
- project name
- user name
- data loading status

The main table contains the stakeholder requirements available for the selected project.

![System Connections](/images/help/SystemConnections.jpg)

## Main actions

The page contains the following main actions:

- **Import**
- **Export**
- **Help**
- **Add Stakeholder Requirement**

## Import

Use **Import** to import stakeholder requirements from a file.

The import file may be one of the supported formats shown in the import dialog.

Typical formats may include:

- XML
- XLSX
- CSV

After selecting a file, the import dialog can be used to start the import.

## Export

Use **Export** to export stakeholder requirements from the current project.

The export dialog allows you to choose the export format.

Available export formats may include:

- XLSX
- CSV
- PDF
- XML

The export dialog may also include options such as whether inactive requirements should be included.

## Add Stakeholder Requirement

Use **Add Stakeholder Requirement** to create a new stakeholder requirement.

When adding or editing a stakeholder requirement, a dialog is opened with several tabs.

## Edit dialog

The edit dialog contains the following tabs:

- **Basis Info**
- **History**
- **Attachments**
- **Notes**
- **Links**
- **Linked To ...**

## Basis Info

The **Basis Info** tab contains the main information about the stakeholder requirement.

Depending on the project configuration, the fields may include information such as:

- requirement code
- requirement name
- requirement description
- status
- priority
- owner
- dates
- other project-specific fields

Some fields may be read-only, while others can be edited.

Required fields may be marked with an asterisk.

## History

The **History** tab shows previous changes to the stakeholder requirement.

The history table may include:

- changed date and time
- changed by
- version

This can be used to understand when the requirement was updated and by whom.

## Attachments

The **Attachments** tab shows files attached to the stakeholder requirement.

Use **Add Attachment** to add a new file.

When adding an attachment, select a file and enter a description.

Attachments can be useful for supporting documentation such as:

- drawings
- specifications
- meeting notes
- external documents
- screenshots

## Notes

The **Notes** tab shows notes related to the stakeholder requirement.

Use **Add Note** to create a new note.

Notes can be used for comments, clarification, review input or internal observations.

## Links

The **Links** tab is reserved for links related to the stakeholder requirement.

If the tab shows **Under Construction**, the functionality is not yet available.

## Linked To ...

The **Linked To ...** tab shows relations from the stakeholder requirement to other entities.

This can help show how a stakeholder requirement is connected to other parts of the project, such as system requirements.

## Saving changes

Use **Save** in the edit dialog to save changes.

Use **Cancel** to close the dialog without saving.

## If data is not shown

If no stakeholder requirements are shown, it may be because:

- data is still loading
- no stakeholder requirements exist for the selected project
- there was an error while loading data
- the current user does not have access to the expected data

Check the **Data** field at the top of the page to see whether data has been loaded or whether an error occurred.

## Good practices

- Use clear and consistent requirement names.
- Write descriptions so they can be understood by both technical and non-technical stakeholders.
- Add notes when clarification is needed.
- Use attachments for supporting documentation.
- Use relations to connect stakeholder requirements to relevant system requirements.
- Export the list when requirements need to be reviewed outside the system.
